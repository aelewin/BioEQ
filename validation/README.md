# BioEQ Validation Module

This directory contains the **independent black-box validation assets** for the BioEQ application.

## Purpose

Black-box validation verifies that BioEQ produces correct results by comparing its output against
reference values generated by independently validated software (e.g., SAS Proc GLM/MIXED, Phoenix
WinNonlin) or against published reference values from peer-reviewed bioequivalence literature.

This module is intended to be re-run:
- After **initial installation** of the BioEQ application
- After **updating R packages** (especially `nlme`, `lme4`, `lmerTest`, `replicateBE`, `PowerTOST`)
- After **upgrading R itself**
- After **any code changes** to BioEQ analysis functions
- On a **scheduled cadence** for ongoing qualification (e.g., quarterly)

## Critical Design Principle: Always Compute Fresh

> **The BioEQ application will execute every analysis in this validation suite from raw data on
> every run. It will NEVER load pre-computed BioEQ results from cache, disk, or memory.**

This is enforced by the validation runner ([R/validation_runner.R](../R/validation_runner.R)),
which loads each input dataset directly from the `datasets/` folder, runs the relevant BioEQ
analysis function in a fresh call, and only then compares the *just-computed* result against the
stored reference values.

The only stored values used for comparison are:
1. **Input data** (`datasets/*.csv`) — never modified
2. **Reference results** (`expected_results/*.csv`) — generated externally by validated software
   (SAS, WinNonlin) or transcribed from peer-reviewed publications; never modified by the app

## Manifest Schema (`manifest.csv`)

| Column          | Description                                                                                  |
|-----------------|----------------------------------------------------------------------------------------------|
| `dataset_id`    | Unique identifier used by the validation runner                                              |
| `name`          | Human-readable name shown in the UI                                                          |
| `group`         | Logical grouping for selection (NCA, ABE, ABEL, RSABE, Parallel, Replicate)                  |
| `layer`         | Which BioEQ layer is exercised: `NCA`, `ANOVA+BE`, or `Both`                                 |
| `design`        | Study design (e.g., `2x2x2`, `Parallel`, `TRTR\|RTRT`)                                       |
| `n_subjects`    | Number of subjects in the dataset                                                            |
| `description`   | Brief description shown in the UI table                                                      |
| `citation`      | Source / publication / package citation                                                      |
| `data_file`     | Relative path to the input data CSV (under this directory)                                   |
| `expected_file` | Relative path to the reference results CSV (under this directory)                            |
| `status`        | One of: `available`, `partial`, `placeholder` (see below)                                    |

### Status values

- **`available`** — Both the input data and the reference results are populated. The runner will
  perform the full comparison and emit PASS/FAIL conclusions.
- **`partial`** — Input data is present but reference results are pending. The runner will execute
  the BioEQ analysis and display the computed values, but cannot return PASS/FAIL.
- **`placeholder`** — Neither input data nor reference results are populated yet. The dataset is
  registered in the UI for visibility but the run action will report "data not available".

## Expected-Results CSV Schema

Each `expected_results/<dataset_id>.csv` follows the same schema:

| Column            | Description                                                                              |
|-------------------|------------------------------------------------------------------------------------------|
| `parameter`       | Parameter name (e.g., `Cmax`, `AUC0t`, `lambda_z`, `PE_pct`, `CI_lower_pct`)             |
| `scope`           | `subject` (per-subject value) or `study` (study-level summary)                           |
| `subject`         | Subject ID when `scope=subject`; blank when `scope=study`                                |
| `treatment`       | Treatment ID (e.g., `R`, `T`) when applicable; blank otherwise                           |
| `expected_value`  | The reference value from validated software or publication                               |
| `tolerance_type`  | `relative` \| `absolute` \| `exact`                                                      |
| `tolerance_value` | Numeric tolerance (ignored for `exact`)                                                  |
| `unit`            | Unit of measurement (informational)                                                      |
| `reference_source`| Software/publication that produced the expected value                                    |
| `notes`           | Free-form notes                                                                          |

### Tolerance semantics

- `relative`: PASS if `|computed - expected| / |expected| <= tolerance_value`
- `absolute`: PASS if `|computed - expected| <= tolerance_value`
- `exact`:    PASS if `as.character(computed) == as.character(expected)` (used for BE conclusions)

## Adding a New Validation Dataset

1. Place the input data at `datasets/<dataset_id>.csv`
2. Place the reference results at `expected_results/<dataset_id>.csv` (use the schema above)
3. Add (or update) the row in `manifest.csv`
4. Set `status = available` (or `partial` if reference values are still pending)
5. Re-launch the BioEQ Shiny app — the new dataset appears automatically in the Validation tab
